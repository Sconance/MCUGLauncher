# 原生 UI 重构：修订流程

原计划按“页面顺序”推进，会在功能未覆盖时被迫保留 WebView，且视觉与状态模型滞后。改为**先模型、后页面、最后切换**。

## 阶段 A：功能对齐清单（当前）

以 `Ui/*.js` 与 `LauncherApplication` 命令为准，建立“功能 → 原生页面 → 状态”矩阵；未覆盖项不得删除 WebView。

## 阶段 B：类型化中间层（下一步）

- 定义 `LauncherState`、`InstanceInfo`、`TaskInfo`、`AccountInfo`、`ContentItem`；
- `LauncherFacade` 暴露 `StateChanged` / `TasksChanged` / `LaunchResult` 事件；
- 页面不再直接读 `JsonElement`；
- 保留 `HandleAsync(json)` 作为兼容层，直到 WebView 退出。

## 阶段 C：页面补齐（按依赖）

1. 实例：设置、导出、更新检查；
2. 下载：详情、版本选择、安装选项；
3. 账号：MUA 档案、皮肤；
4. 社区/收藏/存档/数据源/维护；
5. 首页社区卡片与公告。

## 阶段 D：视觉对齐

- 逐页对照 `styles.css` 与截图；
- 组件：卡片、列表行、标签、进度条、空状态、Toast、对话框；
- 960×640 / 1280×800 / 1920×1080 截图验收。

## 阶段 E：移除 WebView 主界面

仅当阶段 A 清单全部为“已完成”且真实账号/下载/启动验收通过后：

- 删除 `MainWindow`、`Ui/`、`bridge.js`、WebUiChecks；
- 保留微软登录 WebView2。
