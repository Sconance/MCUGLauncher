# 国际化（i18n）

## 结论先说

**只改前端不够。** 界面自己的文案（按钮、标题、说明）确实全在前端，可以直接迁；但有两类文字来自 Rust 侧：

| 来源 | 例子 | 现状 | 处理方式 |
| --- | --- | --- | --- |
| 前端 UI 文案 | 导航、按钮、占位符 | 硬编码中文 | 迁到语言包，`t()` 取值 |
| 命令返回的反馈 | `SavedInfo.message`：`"已收藏 Sodium。"`、`"实例不存在。"` | 后端拼好中文返回 | 后端补 `messageKey` + `params`，前端翻译；`message` 保留作兜底 |
| 错误对象 | `ApiError.message` | 已有 `code` 字段，message 是中文 | 前端按 `code` 映射，忽略 message |
| 业务数据 | 实例名、存档名、公告正文、内容简介 | 中文，属于用户数据或 demo 数据 | **不翻译**；公告/推荐这类产品文案由服务端按语言下发 |

所以本轮先把前端框架与外壳/下载页跑通，后端契约的改造列在最后。

## 目录结构

```
src/i18n/
├── index.tsx           Provider / useI18n / t() / 语言检测与持久化
└── messages/
    ├── zh-CN.ts        基准语言包（key 以它为准）
    └── en-US.ts        英文包，类型是 typeof zhCN，缺 key 会编译报错
```

## 用法

```tsx
import { useI18n } from '../i18n';

function Example() {
    const { t } = useI18n();
    return <button>{t('common.search')}</button>;
}
```

- 带变量：语言包里写 `'搜索{sections}……'`，调用 `t('download.searchPlaceholder', { sections: '模组' })`。
- 找不到 key 时依次回退：当前语言 → 中文 → 返回 key 本身（界面上能一眼看出漏翻）。
- 语言选择存在 `localStorage['mcug.locale']`，同时同步 `<html lang>`。
- 首次启动按 `navigator.language` 猜：`zh*` → 简体中文，其余 → English。

## 语言包扩展（像资源包一样）

内置只有简体中文和 English。想加别的语言不用改代码、不用重新编译：写一个 `.json` 语言包，在 **设置 → 外观 → 界面语言 → 导入语言包…** 里选它即可，导入后立刻切换过去。

### 文件格式

```json
{
  "code": "zh-TW",
  "name": "繁體中文",
  "nativeName": "繁體中文",
  "regionName": "台灣",
  "author": "MCUG",
  "version": "1.0.0",
  "messages": {
    "nav": { "home": "啟動", "download": "下載" },
    "common": { "search": "搜尋" }
  }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `code` | 是 | BCP 47 形式（`zh-TW`、`en-GB`、`pt-BR`），不能和内置的 `zh-CN`、`en-US` 重名 |
| `nativeName` | 否 | 该语言对自己的称呼（`繁體中文`）；缺省回落到 `name` 或 `code` |
| `regionName` | 否 | 地区名，同样用该语言自己写（`台灣`、`United States`） |
| `name` | 否 | 旧字段，仅作 `nativeName` 缺失时的兜底 |
| `author` / `version` | 否 | 只用于展示与排查 |
| `messages` | 是 | 与 `zh-CN` 相同的嵌套结构；可以只写想覆盖的部分 |

语言下拉不显示 code，采用 Minecraft 的写法 **`语言名 (地区名)`**，两边都用该语言自己的写法，所以切换界面语言时列表文字不会变：

- `简体中文 (中国大陆)`
- `English (United States)`
- `繁體中文 (台灣)`

`regionName` 缺失时只显示语言名（`Esperanto`）。

可以直接拿仓库里的示例改：`docs/examples/zh-TW.lang.json`。

### 合并与回退

- 查找顺序：**当前语言包 → 简体中文 → key 本身**。所以语言包只翻译一半也能用，没翻的会显示中文而不是空白。
- 内置包不可覆盖、不可删除；导入同 `code` 的包会替换旧的那份。
- 删除当前正在用的外部包时，界面自动退回简体中文。

### 存储位置

导入的语言包存在 `localStorage['mcug.languagePacks']`（JSON 数组），跟随 WebView 的站点数据，卸载/清缓存会丢。单个包几十 KB，正常大小完全够用；不适合塞图片之类的资源。

### 已知限制

- 目前只支持"导入文件"，不会自动扫描某个目录。要做成免导入的目录扫描，需要加一个 Tauri 命令读 `appDataDir()/languages/*.json`（和语言包同一份 JSON 结构），前端把 `readStoredPacks()` 换成命令结果即可。
- 不做复数规则与 RTL 排版；阿拉伯语这类从右往左的语言还需要在 `document.documentElement.dir` 上单独处理。

## 新增文案的流程

1. 先在 `zh-CN.ts` 加 key（不会影响现有界面）。
2. 再在 `en-US.ts` 补同样的 key（`typeof zhCN` 会强制检查结构）。
3. 组件里用 `t()` 替换硬编码字符串。

命名按「域.子域.名称」，域对齐页面或组件：`nav.*`、`common.*`、`settings.*`、`download.*`。新增页面时加自己的域，不要把所有 key 平铺在顶层。

## 后端要配合的部分

### 1. `SavedInfo.message`（优先级最高）

收藏、重命名、安装、备份等操作都会返回一句中文。国际化后会出现「界面英文、提示中文」。

建议给 `SavedInfo` 加两个可选字段（向后兼容）：`messageKey: string`（语言包 key）与 `params: Record<string, string>`（占位符变量）。改完后一条返回大致长这样：

```json
{
  "message": "已收藏 Sodium。",
  "messageKey": "saved.bookmark.added",
  "params": { "name": "Sodium" },
  "changed": [],
  "entityIds": ["sodium"]
}
```

前端渲染时优先 `t(messageKey, params)`，没有再退回 `message`。改动涉及 `schemas/operations.schema.json`、Rust 各命令、`dto:generate`。

### 2. `ApiError`

已有 `code`，前端按 `code` 建映射表即可，例如 `code === 'instance_not_found'` → `t('errors.instanceNotFound')`。`message` 保留用于日志。

### 3. 服务端下发的文案

公告、推荐语、名言这类内容目前由 demo 数据或数据源提供。真实实现应让数据源返回带语言标记的文案，或由启动器按当前语言请求，前端不参与翻译。

## 注意

- **导航胶囊宽度**：`.nav-pill` 的宽度由 `syncSceneBar()` 写进 `--nav-bar-w`，语言切换后必须重新测量，否则文字会溢出白底。`Shell.tsx` 里已有依赖 `locale` 的 effect 处理，新增其它随文案变宽的元素时留意同类问题。
- 英文比中文长，按钮/标签要允许换行或加 `min-width`，别写死宽度。
- 暂不做复数规则（`1 mod` / `2 mods`）。需要时在语言包里写两条 key（`x.one` / `x.other`），不要引入 ICU 依赖。
