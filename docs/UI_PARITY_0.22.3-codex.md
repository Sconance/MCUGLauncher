# 0.22.3-codex 对照修订

产品基线固定为 `origin/0.22.3-codex` 的 `6c091c66c8ba901ca897f293b570178df674c474`。对照源文件：Ui/home-page.js、navigation.js、settings-page.js、community-pages.js、account-modals.js、instance-pages.js、resource-pages.js 以及实际事件绑定模块。

## 上轮问题

上轮从 Avalonia 起步分支复用 App/Core 分层后，擅自重排了主页、合并了页面和弹窗，并把菜单能创建当成功能覆盖。虽然提交祖先包含 codex 基线，产品行为并没有逐项对齐；此前“完整迁移”的结论不准确。

## 保留而不重写的内容

数据源保存与使用分离、自动/手动测试、资源明确版本与目标选择、下载队列、游戏会话、实例克隆/导出/更新/卸载预览、存档恢复仍使用原 App/Core 后端。该轮不修改这些业务实现，不回退之前的空目录/空源修复。

原网页中只用于演示或明确未实现的能力不伪装成可用功能，例如固定 Mod 更新、游戏内离线皮肤上传、披风上传及假社区身份。对应限制须在界面和文档中说明。

## 验证范围

NativeUiChecks 的 CodexParity 专门检查菜单顺序、默认主页分区、实例展开/收起、主页账号控件、账号/皮肤/服务器/公告弹窗入口、下载默认页与推荐分类、社区密钥、基础窗口尺寸等。另保留既有资源、任务、数据源与账号回归。

这些检查覆盖入口与命令行为，不等于逐像素还原或所有真实账号、游戏环境已验收。后续不能再以菜单存在作为“所有功能完整”的证据。


## 第二轮：按原 CSS 的实际布局关系纠正错位

参照同一产品基线的 home-page.js/styles.css：标题栏 52px、主页两列 320px/弹性列（窄窗口左列 280px）、账号卡 426px、启动按钮 78px，右侧公告 112px、底部语录横条 100px。操作按钮靠右、账号说明贴底、启动图标与文字作为整体居中。小窗口继续允许纵向滚动，不把卡片内容压缩到不可点击。

- 普通 WrapPanel 不再承担目录选择、卡片标题操作区等必须撑满行的布局；使用 Grid 的弹性列和自动宽度列。
- 实例分组箭头恢复左侧，整个标题行可点击；目录框伸展到添加按钮之前。
- 搜索框单独占一行、筛选项在下方；资源列表恢复按可用宽度分列。
- 资源说明与安装选项分居左右，窄弹窗降为上下两行；下载目标和明确版本选择的协议不变。
- 数据源恢复标签/地址/测试按钮同一行，结果位于地址下方；保存、启用和自动测试行为保留。
- 顶部任务进度显式清除原生控件默认最小宽度，防止超出摘要区域。

NativeUiChecks 新增几何位置断言，并保存主页三种尺寸、实例面板、下载目录、资源详情和数据源截图。已检查截图；这些仍是模拟数据下的原生渲染，不是原网页与 Avalonia 的逐像素对比，也不代替真实账号和游戏测试。本轮不修改 App/Core。


## 第三轮：按钮文案与状态配色

以产品基线 styles.css 最后一次 :root 覆盖值为准，不能误用文件前部旧调色板。普通按钮为白底灰字（#414B55），次要按钮为浅蓝底深蓝字（#E8F2F8 / #0B4F7A），主要按钮为蓝底白字（#006DB8 / #FFFFFF），链接、导航、账号页签分别处理。启动按钮保留原渐变；禁用主按钮使用浅蓝灰，不套用默认主题的灰黑色。

主按钮悬停 #2C6193、按下 #005A99、禁用 #ACC3D9；内嵌控件的文字也须保持白色。移除全局 TextBlock 前景色覆盖，并用独立 Button ControlTheme 隔离 Fluent 内部状态选择器。只覆盖 Template 而不隔离 ControlTheme 会导致悬停后内部文字变黑，新增的实际鼠标状态检查覆盖了这个问题。

按原文案恢复搜索/刷新列表、打开登录窗口、登录 MUA、本地 PNG 皮肤/恢复默认头像、查看更多和下载。收藏按钮显示空心/实心心形，由已有 Favorites 状态回推确认；数据源页签与推荐分类选中态同时同步。未重写业务流程。

保存 button-states/button-hover/button-disabled 截图；NativeUiChecks 同时检查普通/次要/主按钮文字、悬停/按下/禁用、源页签选中和收藏状态。未宣称每个页面已经逐像素一致。


## 第四轮：版本类型、管理动作与窗口外框

这是用户明确追加的 UI 需求，允许更改原常驻状态栏和系统标题栏：

- 原版清单不再仅返回最近 24 个正式版；原生 VanillaPage 独立负责正式版、快照版、远古版、全部、搜索和每页 50 条的展示。DownloadPage 只负责社区资源，移除重复的原版分支。
- 已安装实例的管理页增加加载器入口，取实例真实 Minecraft 版本，不把自定义实例名称当作版本号。复用 InstallDialogs/InstallationCommands；该流程生成加载器版本并保留原版，不声称在同目录原地改造现有整合包。
- 版本管理按钮按当前实例、内容管理、本地文件分组；返回按钮回到页头右侧。
- 删除底部常驻状态文字。必要反馈保留为顶部临时、可关闭的提示，不丢弃失败信息。
- 使用当前 Avalonia 11.3 的 ExtendClientAreaToDecorationsHint / NoChrome / BorderOnly，把最小化、最大化/还原、关闭放入主 UI 顶栏；窗口生命周期留在 ShellWindow，拖动避开交互按钮，保留 Windows 边缘缩放。

实际 Windows 验收：已观察系统标题栏消失；内嵌最大化/还原可用；标题栏拖动使位置从 (312,312) 变为 (362,362)；右边缘缩放使宽度从 1200 变为 1100。随后桌面锁屏，未继续点击实际版本列表或验收真实加载器安装；不能把 Headless 的安装命令检查写成真实安装已成功。未关闭用户游戏。

NativeUiChecks 检查快照/历史筛选、快照安装目标、实例加载器使用基础版本、临时通知、最大化/还原；WebBridgeChecks 检查清单无 24 项截断。框架参考：[Avalonia Window API](https://api-docs.avaloniaui.net/docs/T_Avalonia_Controls_Window)。
